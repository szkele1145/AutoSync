# 客户端配置（`mcpatch.yml`）

`mcpatch.yml` 是客户端唯一的配置文件，**文件名固定、大小写敏感**，必须和 `AutoSync-1.0.0.jar` 放在同一个目录。

* 没开版本隔离（HMCL / PCL 的"版本隔离"开关）：目录是 `.minecraft/`
* 开了版本隔离：目录是 `.minecraft/versions/<版本名>/`

本文按下表逐键说明。**默认值 = 不写这一项时程序用的值**（取自客户端 `AppConfig`）。

---

## 0. 完整示例

把下面这份存成 `mcpatch.yml` 放在 jar 同级目录，改一下 `urls` 就能用：

```yaml
urls:
  - mc.example.net:8123
base-path: '.'
version-file-path: version-label.txt
allow-error: false
window-title: AutoSync
show-has-update-message: false
show-no-update-message: false
mirror-mode: false
mirror-backup: true
source-mode: auto
auto-select-source: true
manual-source: ''
source-cache-seconds: 3600
download-threads: 32
concurrent-files: 2
tcp-timeout: 15000
retries: 3
detect-mod-conflicts: true
```

> 仓库里的 [client/mcpatch.yml](../client/mcpatch.yml) 是**带注释的完整模板**，可以直接复制。

启动器里给这个版本加上 JVM 参数：

```
-javaagent:AutoSync-1.0.0.jar
```

（如果是版本隔离，参数里写相对路径即可，启动器的工作目录就是版本目录。）

## 1. 更新源

### `urls`（必填）

* **类型**：字符串列表，格式 `主机:端口`
* **默认值**：空列表（不写就等于没有更新源，客户端会报错退出）
* **说明**：MSFP 裸 TCP 的更新源地址，通常指向 frp 隧道暴露出来的公网地址。可以写多个（同一台的多入口、或多台服务端），客户端会**并发测速后选最快的**；测速失败时按书写顺序依次尝试。

```yaml
urls:
  - mc.example.net:8123
  - backup.example.net:8123
```

**建议值**：至少写 1 个；有条件就写 2 个（一台挂掉自动切另一台）。**不要**写 `http://` 前缀——这个协议不是 HTTP。

### `auto-select-source` / `manual-source` / `source-cache-seconds` / `source-probe-timeout` / `source-weight-speed` / `source-weight-latency`

| 键 | 默认值 | 含义 | 建议 |
| --- | --- | --- | --- |
| `auto-select-source` | `true` | 启动时并发测速所有 `urls`，按综合得分选最优源 | 保持 `true` |
| `manual-source` | `''` | 手动锁定某个源（写 `urls` 里的某一项），填了就跳过测速 | 只在排查时临时用 |
| `source-cache-seconds` | `3600` | 测速结果缓存时间（秒） | 保持默认；源不稳定可降到 `600` |
| `source-probe-timeout` | `5000` | 单个源的测速超时（毫秒） | 移动网络差可升到 `8000` |
| `source-weight-speed` | `0.8` | 综合评分里吞吐的权重 | 保持默认（玩家痛点是下载慢） |
| `source-weight-latency` | `0.2` | 综合评分里延迟的权重 | 两个权重之和建议 = `1.0` |

### `multi-source-download`

* **默认值**：`true`
* **说明**：开启后，一个**大文件**的分块会轮转分配给多个更新源，叠加多条线路的带宽。前提是所有源上的同名文件内容一致——不一致时 SHA-256 校验会失败并回退重下。
* **建议**：多源且内容一致时保持 `true`；只有一个源时无影响。

### `source-speedtest-file`

* **默认值**：`speedtest.bin`
* **说明**：测速用的文件名（相对更新源根目录）。服务端会在 `dist_dir` 下自动生成一个 512KB 的同名文件。
* **建议**：保持默认。若改动，服务端配置的 `speedtest_name` 必须同步改。

## 2. 路径与版本

### `base-path`

* **类型**：字符串
* **默认值**：`""`（空）
* **说明**：更新起始目录，也就是"文件都放到哪个目录下"。

| 取值 | 含义 |
| --- | --- |
| `''`（空） | 自动搜索 `.minecraft` 的**父目录**作为更新起始目录 |
| `'.'` | 当前工作目录（jar 所在目录） |
| `'..'` | 当前工作目录的上一级 |
| `'ab/cd'` | 当前工作目录下的 `ab/cd` |

* **建议值**：
  * **开了版本隔离 → 必须写 `'.'`**。否则会把文件更新到 `.minecraft` 的上级目录（比如 `versions/` 甚至 `.minecraft` 外面），mods 看着"下载成功"却加载不到。
  * 没开版本隔离 → 用默认的 `''` 或显式写 `'.'` 都可以；推荐显式写 `'.'`，行为更可预期。

### `version-file-path`

* **默认值**：`version-label.txt`
* **说明**：记录客户端当前已同步到哪个清单版本的文件（相对 `base-path`）。客户端靠比对它和远端 `manifest.json` 的 `version` 决定要不要更新。
* **建议**：保持默认。**不要**把要分发的文件起名叫 `version-label.txt`。

---

## 3. 失败行为与提示

### `allow-error`（重要）

* **默认值**：`false`
* **说明**：同步过程中出错（下载失败、校验失败、连接超时……）时是否继续启动游戏。
  * `false` = **中止游戏启动**，玩家看到错误提示，不会带着残缺的 mods 进服；
  * `true` = 忽略错误继续启动。
* **建议值**：**`false`（默认）**。用 `true` 时，一旦某个前置没下下来，玩家会在加载界面直接崩，报错还很难懂；`false` 至少能明确告诉玩家"同步失败了"。

> 图形模式（`-javaagent`）下出错会弹窗让玩家自己选；非图形模式下才严格按这个开关执行。

### `show-has-update-message` / `show-no-update-message`

| 键 | 默认值 | 含义 |
| --- | --- | --- |
| `show-has-update-message` | `true` | 有更新时是否弹更新日志提示框 |
| `show-no-update-message` | `true` | 没更新时是否弹"资源文件暂无更新！"提示框 |

* **建议值**：整合包 / 公共服都设成 **`false`**，少打扰玩家。（旧配置里写 `show-finish-message` 也认，会被这两个键继承。）

### `auto-close-changelogs`

* **默认值**：`0`
* **说明**：更新日志窗口自动关闭的毫秒数；`0` = 不自动关，需要玩家手点。
* **建议**：`0`（让玩家自己看完）或 `5000`（看 5 秒自动关）。

### `silent-mode`

* **默认值**：`false`
* **说明**：`true` = 启动后先在后台静默检查更新，**只有真的要下载文件时才显示窗口**；没有更新就直接进游戏。仅图形模式有效。
* **建议**：想要"存在感最低"就 `true`；调试阶段保持 `false`，方便看日志。

### `window-title` / `disable-theme`

| 键 | 默认值 | 说明 |
| --- | --- | --- |
| `window-title` | `AutoSync` | 更新窗口的标题 |
| `disable-theme` | `false` | `true` = 关掉主题（纯色窗口），排查主题渲染问题时用 |

## 4. 镜像模式（重点）

### `mirror-mode`

* **默认值**：`false`
* **说明**：是否让客户端 `mods/` 目录与服务端清单**完全一致**。

| 取值 | 行为 |
| --- | --- |
| `false`（默认） | **只维护清单里列出的文件**：缺的下、改的重下；清单**之外**的文件（玩家自己加的 mod）一概不碰 |
| `true` | **严格镜像**：清单之外的文件会被清理掉——玩家自己加的 mod、手动换的整合包附属、临时放进去的测试 jar，**全部消失** |

* **建议值**：
  * **公共服 / 整合包分发 → `false`**（默认）。玩家自加的优化 mod（Sodium、Iris 之类）不会被清掉，投诉少。
  * 只有当你确实要求"客户端必须和服务端一模一样、多一个文件都不行"（例如比赛服、反作弊服）才开 `true`。

> **严格镜像的后果**，开之前请想清楚：
> 1. 玩家自己装的任何 mod 都会被移除，包括纯客户端的性能 mod；
> 2. 玩家手动放进 `mods/` 的配置文件、材质包（如果也在分发目录范围内）同样会被清；
> 3. 一旦服务端清单配错（比如 `dist_dir` 指向了空目录），**所有玩家**的 mods 会被清空——客户端有一个兜底：**清单里一个 `mods/` 条目都没有时绝不执行清理**，只打警告。但清单"少了一部分"是没法自动识别的。

### `mirror-backup`

* **默认值**：`true`
* **说明**：镜像模式清理时，是**先移动**到备份目录还是**直接删除**。
  * `true` = 移动到 `<base-path>/.modsync-removed/` 下（保留原来的相对路径结构），可以人工找回；
  * `false` = 直接删除，不可恢复。
* **建议值**：**保持 `true`**。多占一点磁盘，换一次"手滑能救回来"。

### `detect-mod-conflicts`

* **默认值**：`true`
* **说明**：开启后，如果 `mods/` 里存在与清单托管模组 **modId 相同**的非托管 jar（玩家自加的同名模组），会被自动重命名为 `xxx.jar.disabled`，避免 NeoForge 因 `Duplicate mod` 直接崩游戏。
* **建议**：保持 `true`。这是兜底机制——镜像模式开着时基本用不到。

## 5. 下载来源模式（重点）

### `source-mode`

* **类型**：字符串，只能是 `auto` / `cdn` / `server`（不区分大小写）
* **默认值**：`auto`

清单里每个文件条目都带 `urls`，例如：

```json
{ "path": "mods/x.jar", "size": 123456, "sha256": "..",
  "urls": ["mods/x.jar", "https://cdn.modrinth.com/data/xxxx/versions/yyyy/x.jar"] }
```

* 相对地址（`mods/x.jar`）→ 拼到更新源上走 MSFP；
* `http(s)://` 绝对地址 → Modrinth 官方 CDN 直链。

到底用哪个，由 `source-mode` 决定：

| 取值 | 行为 | 什么时候用 |
| --- | --- | --- |
| `auto`（默认） | 每次同步开始时，给 CDN 与自己的更新源**并发测一次速**，哪个快用哪个 | 绝大多数情况。CDN 快就省你的带宽，CDN 被墙/慢就走自己的服务端 |
| `cdn` | 强制走 CDN 直链，**不测速**；某个文件 CDN 失败时照样回退到更新源 | 你的服务器带宽很小、想尽量把流量甩给 Modrinth |
| `server` | 强制走自己的更新源，**完全跳过 CDN**（不测速、不尝试直链） | 服务端在国内且 CDN 被墙；或你要精确控制流量 |

* **建议值**：**`auto`**。
* **兼容旧写法**：`prefer-cdn: true` 等价于 `source-mode: cdn`，`prefer-cdn: false` 等价于 `source-mode: server`。两个都写时以 `source-mode` 为准。

### CDN 测速与调优

| 键 | 默认值 | 含义 | 建议 |
| --- | --- | --- | --- |
| `speedtest-min-size-mb` | `10` | 只有体积 ≥ 它的文件才会被挑来当测速样本（太小的文件测不出带宽） | 保持默认 |
| `speedtest-duration-ms` | `2000` | 每个来源的测速时长（毫秒），CDN 与服务端并发测 | 保持默认 |
| `cdn-prefer-ratio` | `0.5` | CDN 速度 ≥ 服务端速度 × 这个比例就算"够快"，选 CDN（判据 `cdn_speed >= server_speed * ratio`） | 调小更偏向 CDN（省带宽）；调到 `1.0` 以上表示"CDN 必须更快才用它" |
| `cdn-max-threads` | `64` | CDN 测速太慢时，把连接数翻倍重测一次的上限 | 保持默认 |

### `cdn-exclude`

* **默认值**：`[]`
* **说明**：强制走更新源、**不尝试 CDN** 的文件名单。每一项可以是文件名通配（`Flashback-*.jar`）或相对路径（`mods/xxx.jar`，也支持 `mods/lib/*.jar`），**不区分大小写**。
* **建议**：把那些"CDN 上本来就没有"的自托管文件写进来，省掉一次注定失败的 CDN 请求。

```yaml
cdn-exclude:
  - Flashback-*.jar          # 自托管，CDN 上没有
  - mods/lib/*.jar           # 自编译的库
```

### `cdn-timeout`

* **默认值**：`15000`
* **说明**：CDN 直链的连接超时与读超时（毫秒）。只要还在持续收到数据就不会超时，所以可以放得比 `http-timeout` 宽松。
* **建议**：保持默认。

## 6. 并发与超时（重点）

### `concurrent-files` × `download-threads` = 最大连接数

这是最容易把隧道打爆的两个键：

| 键 | 默认值 | 含义 |
| --- | --- | --- |
| `concurrent-files` | `2` | **同时下载多少个文件**（程序内部会夹到 1~16） |
| `download-threads` | `32` | **单个文件切成多少块并发下**（每块一条连接） |
| `download-threshold` | `1048576`（1MB） | 体积小于它的文件不分块，直接单线程下载 |

**最大同时在用的连接数 ≈ `concurrent-files` × `download-threads`**（小文件只占 1 条连接）。

所以默认配置的峰值是 **2 × 32 = 64 条**连接。调之前先想清楚：

* **frp 隧道 / 家宽 / 云服务器的小带宽**：64 条并发连接已经足够打满普通家宽；再加只会互相抢带宽，还可能触发云厂商的连接数限制或 frp 的 `maxPoolCount`；
* **单台客户端的服务端压力**：每个玩家 `concurrent-files × download-threads` 条连接，10 个玩家同时更新就是几百条，服务端要能扛住；
* **真想调大**：优先加 `concurrent-files`（把 TCP 建连和 SIZE 请求的等待时间重叠掉，收益最明显），`concurrent-files` 不建议超过 `8`；
* **下载慢时先降不要升**：`concurrent-files: 1` + `download-threads: 8` 是"保守档"，适合带宽小、玩家多的场景。

**参考档位**：

| 场景 | `concurrent-files` | `download-threads` | 峰值连接 |
| --- | --- | --- | --- |
| 保守（小带宽 / 玩家多 / 隧道不稳） | 1 | 8 | 8 |
| **默认（推荐）** | **2** | **32** | **64** |
| 激进（大带宽专线 / 玩家少） | 4 | 32 | 128 |

> 如果客户端报 `Connection reset` 或大量超时，**先把 `concurrent-files` 降到 1** 再试。

### 超时与重试

| 键 | 默认值 | 含义 | 建议 |
| --- | --- | --- | --- |
| `tcp-timeout` | `15000` | MSFP 的连接超时与读超时（毫秒）。大文件只要还在持续收数据就不会超时 | 移动网络差可升到 `30000` |
| `retries` | `3` | 网络问题的重试次数 | 建议 `timeout × retries` 总时长控制在 20 秒内 |
| `private-timeout` | `7000` | 私有协议超时（毫秒） | 保持默认 |
| `http-timeout` | `7000` | HTTP 系列协议超时（毫秒） | 保持默认 |
| `http-headers` | `{}` | HTTP 系列协议的自定义请求头 | 一般不用填 |
| `ignore-ssl-cert` | `false` | 忽略 HTTPS 证书校验 | 只在自签证书场景临时开 |

### `test-mode`

* **默认值**：`false`
* **说明**：开启后**每次启动都重新下载全部文件**，用来实测网速。会消耗大量流量。
* **建议**：只在测速 / 压测时临时打开，用完记得关。

## 7. 排查用清单

改配置之前，先确认这几件事：

```yaml
urls:
  - mc.example.net:8123     # ① 没有 http:// 前缀，端口就是 frp 暴露的端口
base-path: '.'              # ② 版本隔离必须写 '.'
allow-error: false          # ③ 同步失败要中止启动，而不是带着残缺 mods 进去
mirror-mode: false          # ④ 不确定就先别开镜像
concurrent-files: 2         # ⑤ 报 Connection reset 先降到 1
```

日志在哪：

* 图形模式下更新窗口里就有实时日志，可以直接框选复制；
* 同时会写到 **jar 同级目录**下的 `mcpatch.log`（图形模式）或 `mcpatch.log.txt`（非图形模式）；
* 下载中的临时文件在 `<base-path>/.modsync-temp/` 下，镜像模式清理掉的文件在 `<base-path>/.modsync-removed/` 下（保留原相对路径）。

更多排查见 [常见问题.md](常见问题.md)。
