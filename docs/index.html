AutoSync

Minecraft 整合包 · 自动同步

玩家点一次启动，客户端自动比对服务端清单并下载差异文件，进游戏时版本必然一致。 自研 MSFP 裸 TCP 协议，绕过国内云服务器的 ICP 拦截；CDN 自动测速选源，省服务器带宽。

快速开始 查看源码
javaagent MSFP 裸 TCP CDN 自动测速 Python / MCDR 双服务端 开源 MIT
它解决什么问题
针对国内中小型 MC 服务器的真实痛点

绕过 ICP 拦截

国内云服务器对未备案的 HTTP 访问会拦截（返回"未备案"页）。AutoSync 自研 MSFP 裸 TCP 协议，不走 HTTP，无需备案、无需域名。

根治版本不一致

镜像模式：客户端 mods/ 强制与服务端清单完全一致，清单外文件移到 .modsync-removed/ 备份。玩家怎么折腾都不会崩在版本上。

省服务器带宽

CDN 自动测速选源：同步前实测 Modrinth CDN 与服务器速度，差距不大走 CDN，CDN 慢则提线程重测，仍慢才用服务器。实测 80.7% 的 mod 可走 CDN。

下载更快

单文件多线程分块 + 多文件并发。实测同样 4 个文件：单线程 1.37 MB/s → 4 线程 3.68 MB/s（2.7 倍）。

出问题看得见

客户端图形窗口内置实时日志：边同步边滚动，能直接看到 [测速]、[CDN]、[服务端] 的决策过程，玩家截图就能反馈。

服务端全自动

扫描分发目录、算哈希、查 Modrinth、生成清单，一条命令完成。另有模组分类、依赖检查（含 JiJ 嵌套）、缺失前置自动下载。

快速开始
服务端 3 步，客户端 3 步

服务端

  1. 放到服务器
    克隆仓库或解压发布包到 /opt/autosync
  2. 生成配置
    首次运行自动创建 config.json
  3. 启动
    把要分发的文件放进 client-dist/，然后启动常驻
# 交互式（推荐）
python3 -m autosync --base . shell

# 常驻服务
python3 -m autosync --base . serve

# 只构建一次清单
python3 -m autosync --base . build

客户端

  1. 放进版本目录
    versions/<版本名>/ 下放 jar 与 mcpatch.yml
  2. 改配置
    把 urls 改成你的更新源地址
  3. 加 JVM 参数
    启动器里给该版本加上 javaagent 参数
# 版本目录内容
AutoSync-1.0.0.jar
mcpatch.yml

# JVM 参数
-javaagent:AutoSync-1.0.0.jar
为什么必须用 javaagent？ 普通 mod 在游戏启动后才生效，而那时 mods/ 里的 jar 已被 JVM 锁定，无法替换。 javaagent 在 Minecraft 加载任何 mod 之前 运行，可以自由读写这些文件。

仓库结构
客户端 / 服务端 / 文档 / 工具
AutoSync/
├── client/                 客户端
│   ├── AutoSync-1.0.0.jar    javaagent（javaagent / 独立进程 / modloader 三种启动方式）
│   ├── mcpatch.yml           配置模板（含全部配置项与注释）
│   └── src-java/             客户端 Java 源码（Gradle 工程）
├── server/
│   ├── python/               独立 Python 版（纯标准库，Python 3.11+）
│   └── mcdr/                 MCDR 插件版 + 打包好的 .mcdr
├── docs/                     全部文档
├── tests/                    164 项测试（仅需标准库）
└── tools/                    上传脚本 · MCDR 打包 · 包结构校验
代码复用：server/mcdr/autosync/core/ 是 server/python/autosync/ 的逐字节副本， 由 tools/build_mcdr.py（跨平台）或 build-mcdr.ps1（Windows）在打包前同步并做 SHA-256 比对， 不一致就中止打包。业务逻辑只写一份。
